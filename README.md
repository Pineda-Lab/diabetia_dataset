This repository contains the code used to describe and validate DiabetIA, and to produce the tables and figures of the data descriptor *DiabetIA: A Longitudinal Electronic Health Record Dataset for Diabetes Research from Mexico* (in preparation). It contains **only code**; no patient-level data are included.

## Overview

DiabetIA is a de-identified longitudinal dataset of primary care electronic health records from six family medicine units of the Mexican Institute of Social Security (IMSS) in Michoacán, Mexico: 136,674 adults followed between 2005 and 2020, summarized in two-year windows per patient. This repository contains the code that characterizes the cohort and assesses the quality of the release. Methods and results are described in the manuscript. DiabetIA is part of the [DiabetIA project](https://pinedalab.ai/diabetia/) of the Pineda Lab (*Proyecto Insignia*).

## Data availability

DiabetIA is owned by IMSS and is freely available, without registration, from the repository of the National Informatics Ecosystem for Health (ENI Salud): <https://repositorio-salud.conacyt.mx/jspui/handle/1000/56>. The release consists of a tabular file in CSV format and its data dictionary. The comparison datasets are obtained from their own sources:

| Dataset | Source and access |
|---|---|
| DiabetIA | ENI Salud, <https://repositorio-salud.conacyt.mx/jspui/handle/1000/56>. Open download. |
| COVID-19 Open Data (Mexico) | Dirección General de Epidemiología, <https://www.gob.mx/salud/documentos/datos-abiertos-152127>. Open download. |
| National Cancer Registry (Mexico) | Public information (transparency) request. |
| SIDIAP, CPRD Aurum, MIMIC-IV | Not processed; values are taken from their published data resource profiles (`LITERATURE` in `diabetia/table2.py`). |

The input files are placed in `data/`, which is not versioned:

```
data/
├── diabetia/            hk_database.csv, data_dictionary.xlsx
├── covid-mx/            COVID19MEXICO*.csv (2020–2024)
└── registro-cancer/     Mexico-RegistroNacionalCancer2020.xlsx
```

The comparison datasets are optional: when they are absent, their columns of Table 2 are reported as "–".

## Requirements

- Python ≥ 3.9, with the dependencies pinned in `requirements.txt` (pandas 2.3.3, NumPy 2.0.2, openpyxl 3.1.5, tqdm).
- R ≥ 4.1, with `data.table`, `ggplot2`, `scales` and `wesanderson`, for the figures.

## How to run

**1. Install the dependencies.**

```bash
git clone https://github.com/Pineda-Lab/diabetia-insignia.git
cd diabetia-insignia
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

For the figures, install the R packages once:

```r
install.packages(c("data.table", "ggplot2", "scales", "wesanderson"))
```

**2. Place the data in `data/`** as shown in [Data availability](#data-availability). Only `data/diabetia/hk_database.csv` is required; the comparison datasets are optional.

**3. Run the pipeline** from the root of the repository:

```bash
./run_all.sh              # all tables and figures
./run_all.sh summary      # Tables 1, 2 and S1; Figures 1, 3 and S1
./run_all.sh validation   # Tables S2, S3 and S7–S9, re-identification risk; Figures 4 and S2
```

`run_all.sh` uses `python3`; set `PYTHON=/path/to/python` to use another interpreter. Datasets missing from `data/` and, when R is not installed, the figures are skipped with a message.

**4. Find the results in `results/`:**

| Folder | Content |
|---|---|
| `manuscript/` | Tables 1 and 2 and Figures 1, 3 and 4 (e.g. `figure_3_patient.png`) |
| `supplementary/` | Supplementary Tables S1–S3 and S7–S9 and Supplementary Figures S1 and S2 |
| `auxiliary/` | Intermediate values cited in the text (cohort, k-anonymity, figure statistics) |
| `patients/` | Candidate patients for Figure 3 (internal use only) |

Tables are written as `.csv` and as `.html` formatted to be pasted into a word processor. Figure 2 is a diagram drawn by the authors and is not generated by this code.

**Running a single step.** The Python tables can be generated without the figures with `python3 diabetia/run.py [--only summary|validation]`, which reads the DiabetIA file only once, and each figure with `Rscript diabetia/figure_<name>.R`. The patient of Figure 3 is selected automatically; to review other candidates:

```bash
Rscript diabetia/figure_patient.R --top 3       # the three best candidates
Rscript diabetia/figure_patient.R --profiles    # one patient per clinical profile
```

These candidate figures are written to `results/patients/` and their file names contain the coded patient identifier, so they must not be shared.

The full pipeline takes a few minutes; the COVID-19 files require several GB of memory. The scripts are deterministic, and the manuscript results were produced with Python 3.9.6 on macOS.

## Notes for users

- Each row of the tabular release is a two-year window of one patient (`x_start`–`x_end`) followed by a one-year outcome period (`y_start`–`y_end`); successive windows overlap by one year.
- The analyses exclude the 457 patients without a visit in any window (136,674 patients, 475,924 windows). Windows without a visit have no measurements.
- The baseline of each patient is the first window with at least one visit.
- Values beyond the limits in `diabetia/limits.csv` are counted, not removed.

## Privacy

DiabetIA is de-identified but not anonymous, because it keeps exact dates. Users must not attempt to re-identify patients or to link the data with other sources. The outputs in `results/patients/` list individual patients and are for internal use only.
